# Illustrated Explainer（图解式讲解）

把一个项目或一门技术，讲给**完全没有基础的人**听。核心公式：

**一节 = 一张图 + 两三段白话 + 一句「带走这句话」。**

整篇从最基础的概念出发，走到「这个项目是怎么做的」，再向外拓展到工具、场景和学习路线。

## 1. 先搞清楚三件事

开写前确认（能从对话推断就别问）：

1. **读者是谁**：零基础到什么程度？（例：「动画和前端小白」→ 不能假设懂 CSS、帧率、插值。）
2. **放在哪**：新建 Notion 页面，还是重写已有页面？重写时保留原页面，用 `replace_content` 替换正文、更新标题，链接不变。
3. **读者的兴趣点**：用户点名的方向（例：「对 Blender 感兴趣」）要单独成节，并给出可以动手的步骤。

## 2. 文章骨架（按这个顺序）

| 部分 | 作用 | 典型节数 |
| --- | --- | --- |
| 导读提示框 | 写给谁、怎么读、会学到什么（用 → 串起来） | 1 个提示框 |
| 基本功 | 理解项目必需的通用概念，从最底层讲起 | 3–5 节 |
| 这个项目怎么做的 | 用基本功解释项目的关键设计和流程 | 3–5 节 |
| 技术位置表 | 每个工具在流程里的哪一环、一句话作用；标注「第一次读可跳过」 | 1 节 |
| 向外拓展 | 工具地图、用户感兴趣的方向（多种接法）、更多应用场景 | 2–4 节 |
| 学习路线 | 路线图 + 本周就能做的 3 个小练习（待办清单） | 1 节 |
| 附录 | 小词典；在本项目里动手的命令和「想改什么去哪找」 | 2 节 |

每一节的固定结构：

1. `## 序号. 标题`：标题用读者能懂的话，例如「缓动：速度的形状」，而不是「Easing 函数」。
2. 插图（每节至少一张）。
3. 两三段白话：先说现象，再说原理，最后说这个项目里的具体数字。
4. 可选：一个小练习，答案放在图里。
5. 蓝色提示框：`带走这句话：……`，一句话，能独立成立。

## 3. 写作风格

- 用「你」对读者说话，口吻像一个耐心的朋友。不用「本文」「笔者」。
- 先给比喻，再给术语。好比喻要能对上机制：「录像带 vs 计算器」解释纯函数时间轴，「弹簧上的小方块」解释弹簧缓动。
- 术语第一次出现时加粗，并马上用一句白话解释。
- 用项目里的真实数字（ω = 24、0.19 秒、840 帧），不用「很快」「很多」这类形容词。
- 句子短，段落不超过 3 句。列表只用于并列的东西。
- 给出取舍和审美判断：「来回弹的看着好玩，用在界面上却显得廉价」。新手最缺的就是这种判断。
- 查询性质的内容（技术表、词典、命令）放后面，并说明「第一次读可以跳过」。
- 练习写成待办清单（`- [ ]`），每个练习都要小到一周内能完成。

## 4. 插图（SVG）规范

每张图只讲**一个想法**，图本身要能独立看懂。

- **画布**：宽 800，高按内容定（280–500）。浅暖灰圆角底 `#F5F3EF`，在 Notion 浅色和深色模式下都清楚。
- **配色**：墨黑 `#1A1917` 加一个强调蓝 `#2F5BEA`，灰色 `#7A756C` 用于说明文字，必要时加一个警示橙 `#B4502E` 表示「别这样」。不用渐变。
- **字体**：中文字体栈 `'PingFang SC','Hiragino Sans GB','Noto Sans SC','Microsoft YaHei',sans-serif`。插图以图片形式显示，网页字体用不了。
- **图内自带标题和副标题**：左上角 19px 粗体标题，下面一行 13.5px 灰色副标题，说清这张图要看什么。
- **直接标注**：文字写在图形旁边，不用图例。数值标签用等宽字体。
- **常用图型**：

| 想讲的东西 | 画法 |
| --- | --- |
| 由很多片段组成（帧、步骤） | 胶片条或一排卡片 |
| A 变成 B、中间是计算出来的 | 两端实心、中间虚线幽灵态，下方加时间轴和公式框 |
| 多种做法对比 | 并排小图 + 每个一句评语，推荐项用强调色描边 |
| 两个参数的影响 | 2×2 小曲线网格，标出推荐格子 |
| 两种思维方式 | 左右两栏：左边灰色打叉，右边蓝框打勾 |
| 流程或流水线 | 编号方框 + 箭头，支线用强调色汇入 |
| 时间编排 | 时间轴：上方状态色带，下方刻度和事件标记 |
| 工具分类 | 2×2 象限图，标出「我们在这里」 |
| 场景合集 | 卡片网格：图标 + 名称 + 工具 + 「复用：……」 |
| 学习路线 | 蜿蜒的路径 + 站点 + 末端分叉成几个方向 |

- 曲线类的图要**预留上下空间**（过冲会冲出框），纵轴范围单独设定，不要按 0–1 画。
- 用 `scripts/svgkit.py` 里的工具函数画图（`T` 文字、`R` 矩形、`C` 圆、`L` 线、`P` 路径、`arrow` 箭头、`head` 标题、`spring`/`poly` 曲线），把所有插图写在同一个生成脚本里，方便统一修改。

## 5. 预览并修图（必须做）

```bash
python scripts/preview.py <svg目录> <输出png目录>
```

逐张查看 PNG，重点检查：

- 文字超出卡片或画布（中文比估计的宽）；
- 元素互相重叠（标签压在虚线或曲线上）；
- 曲线冲出绘图框；
- 右侧内容被截断。

改完重新生成再看一次。预览脚本把 SVG 内联进页面再截图：截图裸 SVG 文件会超时，而在 `about:blank` 里用 `<img src="file://…">` 加载会是空白图。

## 6. 可选：交互小实验

一个最能「玩出感觉」的概念（参数调节、曲线变化），值得做成单文件 HTML 嵌进页面：

- 单文件，不依赖外部资源，小于 200 KB；配色和插图一致，固定浅色。
- 打开就处于有意义的状态，带 3–4 个预设按钮，读数旁边给出一句评价（例：「干净利落，适合界面」）。
- 尊重 `prefers-reduced-motion`。
- 写完用 Playwright 截图检查一次，并确认控制台没有报错。

范例：`assets/spring-lab-example.html`。

## 7. 发布到 Notion

详细步骤和坑见 `references/notion.md`。要点：

1. 先读 `notion://docs/enhanced-markdown-spec`。
2. 用 `notion-search` 找到目标位置（父页面或要重写的页面）。
3. 每个文件先调用 `notion-create-file-upload`，再用 `curl -F` 从本地上传。不要把 SVG 内容贴进 `create-attachment`，太费 token。
4. **上传后 1 小时内必须放进页面**，所以先把所有图准备好，再集中上传，然后马上写页面。
5. 图片写 `![说明](file-upload://<id>)`，HTML 写 `<embed src="file-upload://<id>">标题</embed>`。
6. 写完用 `notion-fetch` 读回检查，修掉自动链接这类问题。
7. 告诉用户你只能读回页面的文字内容，看不到它实际显示出来的样子，请他确认图片和嵌入都能正常显示；如果有图显示不了，就换成 PNG 重新上传。

## 8. 交付前检查清单

- [ ] 每节都有图、白话解释和「带走这句话」
- [ ] 所有术语第一次出现都有白话解释
- [ ] 用户点名的兴趣方向单独成节，有可以照做的步骤或代码
- [ ] 至少一节「还能用在哪」，给出用户可能没想到的场景
- [ ] 学习路线 + 3 个本周能做的练习
- [ ] 所有插图都预览过，没有溢出和重叠
- [ ] Notion 页面读回检查过（自动链接、表格、提示框都正常）
- [ ] 回复里说明了结构、改动，以及请用户确认图片显示
